## SLIDE 02 — 우리가 직면한 현실

### 국내 드론 시장 현황

| 지표 | 현재 수치 | 의미 |
|------|----------|------|
| 국내 드론 등록 대수 | **90만 대+** | 매년 30% 이상 증가 |
| 저고도 공역 레이더 사각지대 | **67%** | 기존 레이더가 탐지 못하는 구간 |
| 수동 관제 평균 반응시간 | **5분** | 고속 드론 위협에 대응 불가 |
| 고정 레이더 구축 비용 | **수억 원 + 6개월** | 긴급 상황 적용 불가 |

### 2030년 예정 변화
- **UAM(도심 항공 모빌리티)** 상용 서비스 개시
- 드론 택배·농업·건설·재난대응 동시 운용
- **같은 저고도 공역(120m 이하)에 수천 대 집중**

> **핵심 문제:** 드론은 기하급수적으로 늘어나는데, 관제 기술은 "1대 = 1조종사" 수준에 머물러 있습니다.

**발표자 노트:** 수치를 통해 문제의 시급성을 강조. "지금 이 순간에도 전국 하늘에서 수십만 대가 날아다닌다"는 표현으로 현실감을 높인다.

## SLIDE 03 — 기존 시스템의 한계

### 세 가지 핵심 문제

| 시스템 | 문제점 | 결과 |
|--------|--------|------|
| **K-UTM** (국가 통합 드론관제) | 중앙 서버 1대 장애 → 전체 관제 마비 | 단일 실패점(SPOF) 취약 |
| **고정형 레이더** | 수억 원 + 6개월 구축, 건물에 막혀 67% 미감시 | 긴급 배치 불가 |
| **수동 관제** | 5분 반응 지연, 24시간 5명 상주 인력 | 고속 드론 대응 불가 |

### 드론쇼 방식의 한계
```
기존 드론쇼 방식:
  중앙 컴퓨터 → 경로 계획 → 각 드론에 명령 전달
  (사전에 짠 대본대로만 실행, 돌발 상황 대응 불가)

SDACS 방식:
  각 드론이 스스로 판단 → 충돌 예측 → 자율 회피
  (집단 지능으로 창발, 돌발 상황 실시간 대응)
```

**발표자 노트:** K-UTM을 적으로 삼는 것이 아니라, "보완 관계"임을 강조. SDACS가 K-UTM의 단점을 메우는 솔루션으로 포지셔닝.

## SLIDE 04 — SDACS란 무엇인가?

### 핵심 개념: 이동형 가상 레이더 돔

```
기존 방식:              SDACS 방식:

  [ 지상 레이더 ]         [ 관제드론 ][ 관제드론 ][ 관제드론 ]
        |                    ↓           ↓           ↓
  [ 중앙 서버 ]         ←─────────────────────────────→
        |                    이동형 가상 레이더 돔
  [ 드론들 ]                     (실시간 생성)
                                       |
                               [ 드론들 자율 회피 ]
```

### 비유: "하늘의 신호등"
- **도로의 신호등** → 차들이 서로 부딪히지 않도록 교통 정리
- **SDACS** → 드론들이 서로 부딪히지 않도록 AI가 자동 교통 정리

### 3가지 차별점
1. **레이더를 드론으로 대체** — 고정 인프라 없이 30분 내 긴급 배치
2. **탐지부터 회피까지 완전 자동화** — 사람 개입 없이 0.8초 내 대응
3. **드론 추가만으로 관제 범위 확장** — 운영 인력 80% 절감

**발표자 노트:** "레이더를 드론으로 대체한다"는 개념이 핵심. 청중이 이 문장 하나를 기억하고 나가면 성공.

## SLIDE 05 — 5겹 안전망: 어떻게 충돌을 막는가?

> "하나가 실패해도, 다음 장치가 안전을 보장합니다."

| 단계 | 비유 | 작동 방식 |
|------|------|----------|
| **1단계** 경로 사전 설계 | 내비게이션 | 출발 전 다른 드론과 겹치지 않는 최적 경로 계산 |
| **2단계** 90초 전 충돌 예측 | 전방 레이더 | 현재 속도 유지 시 90초 후 접근 여부 미리 계산 |
| **3단계** 자석형 자동 회피 | 같은 극 자석 | 드론끼리 가까워지면 자동으로 밀어내는 힘 발생 |
| **4단계** 비상 브레이크 | 자동차 ABS | 모든 회피 실패 시 최후의 비상 정지 |
| **5단계** 자동 귀환 | 비상구 | 배터리 부족·고장 시 가장 가까운 착륙지로 자동 복귀 |

### 자동 우선순위 시스템

| 우선순위 | 모드 | 발동 조건 |
|---------|------|----------|
| P0 | 비상 | 충돌 임박 또는 배터리 위험 |
| P1 | 충돌회피 | 10m 이내 드론 감지 |
| P2 | 임무 | 임무 드론 이착륙 중 |
| P3 | 순항 | 정상 비행 이동 중 |
| P4 | 대기 | 공역 위협 없음 |

**발표자 노트:** "5겹 안전망" 비유가 핵심. 자동차의 에어백·ABS·안전벨트 비유 활용 가능.

## SLIDE 06 — 불법 드론 자동 탐지 및 대응

### 탐지 → 퇴각 자동화 파이프라인 (1초 이내)

```
[미등록 드론 발견]
      │
      ▼ (~0.05초)
① 탐지: 전파탐지기 + AI 카메라로 드론 발견
      │
      ▼ (즉시)
② 식별: 드론 고유번호를 DB와 대조 → 등록/미등록/위협 분류
      │
      ▼ (자동)
③ 카운트다운: 미등록 드론에 30초 타이머 부여
      │
      ▼ (자동)
④ 경고: SMS + 앱 푸시 + 멀티채널 경고 발송
      │
      ▼ (최종)
⑤ 퇴각 유도: 관제 드론이 포위 대형 → 심리적 압박 + 전파 경고
```

**전체 소요 시간: 1초 이내 (기존 수동 대응: 평균 5분)**

### 적용 시나리오
- 공항 인근 불법 드론 침입
- 국가 중요 시설(청와대·원전·군사시설) 상공 무단 진입
- 대규모 행사장(올림픽·월드컵) 상공 보안

**발표자 노트:** 정부기관 입장에서 가장 관심 있는 "보안" 기능. 드론 위협 관련 최근 사건 언급으로 현실감 추가.

## SLIDE 07 — 시스템 아키텍처 (기술 개요)

### 4계층 구조

```
┌──────────────────────────────────────────────┐
│  Layer 4: 사용자 인터페이스                    │
│  3D 대시보드 + CLI + 웹 시뮬레이터              │
├──────────────────────────────────────────────┤
│  Layer 3: 시뮬레이션 엔진                      │
│  SimPy 이산이벤트 + Monte Carlo 38,400회       │
├──────────────────────────────────────────────┤
│  Layer 2: 공역 관제 (AirspaceController 1Hz)  │
│  CPA 90초 예측 + Voronoi 공역분할              │
├──────────────────────────────────────────────┤
│  Layer 1: 드론 에이전트 (10Hz)                 │
│  APF 자동회피 + CBS 최적경로 + 상태머신         │
└──────────────────────────────────────────────┘
```

### 핵심 알고리즘 3종

| 알고리즘 | 역할 | 비유 |
|----------|------|------|
| **CPA** (최근접점 예측) | 90초 후 충돌 여부 미리 계산 | 자동차 전방 레이더 |
| **APF** (인공 포텐셜 장) | 드론끼리 자석처럼 밀어내는 힘으로 자동 회피 | 자석의 척력 |
| **CBS** (충돌기반 탐색) | 여러 드론의 최적 비충돌 경로를 한 번에 계산 | 카풀 앱 경로 최적화 |

**발표자 노트:** 비전공자 청중을 위해 알고리즘 이름보다 비유를 중심으로 설명.

## SLIDE 10 — 검증: 38,400회 시뮬레이션

### Monte Carlo 검증 방법론

```
384개 설정값 조합
    × 100개 무작위 시드
    = 38,400회 자동 검증
```

### 검증 범위
- **드론 수**: 10대 ~ 100대
- **기상 조건**: 정상 / 강풍 / 마이크로버스트 / 태풍 / 결빙
- **장애 유형**: 모터 고장 / 배터리 소진 / GPS 재밍 / 통신 두절
- **침입 시나리오**: 미등록 드론 10~25% 혼입

### 63개 시나리오 커버리지

| 카테고리 | 시나리오 예시 |
|---------|-------------|
| 7대 광역시 도시환경 | 서울·부산·인천·대구·광주·대전·울산 |
| 극한 기상 | 마이크로버스트, 태풍 12.9m/s, 결빙, 풍속 전단 |
| 보안 위협 | 불법 드론 침입, GPS 재밍, 적대적 군집 |
| 대규모 확장 | 500대 동시 운용, 메가 배송 시나리오 |

**발표자 노트:** "주사위를 38,400번 굴려서 모든 상황을 검증했다"는 비유 활용.

### K-UTM과의 연동 시나리오
```
K-UTM (사전 경로 승인)
      +
SDACS (실시간 자율 회피)
      =
완전한 저고도 공역 안전 시스템
```
K-UTM을 대체하는 것이 아니라, **실시간 충돌 회피 계층을 보완**합니다.

## 부록 A — 예상 질문 & 답변

### Q1. 실제 드론에 적용할 수 있나요?
현재는 소프트웨어 시뮬레이션 단계입니다. ROS2/PX4 MAVLink 프로토콜과 호환되도록 설계되어 있어, 실제 드론 펌웨어에 SDACS 에이전트를 탑재하면 바로 연동이 가능합니다. 2026년 하반기 Crazyflie 소형 드론으로 첫 실비행 테스트를 계획 중입니다.

### Q2. K-UTM과 충돌하지 않나요?
K-UTM은 사전 경로 승인 시스템, SDACS는 실시간 자율 회피 시스템으로 역할이 다릅니다. K-UTM이 "출발 전 경로를 예약"한다면, SDACS는 "비행 중 돌발 상황에 즉각 대응"합니다. 두 시스템은 보완 관계입니다.

### Q3. 해킹·사이버 공격에 안전한가요?
각 드론 간 통신에 암호화(Zero-trust 아키텍처)를 적용했습니다. 분산형 구조이기 때문에 일부 드론이 해킹당해도 나머지가 정상 작동합니다. 중앙 서버가 없으므로 단일 해킹으로 전체 시스템이 마비되는 문제가 없습니다.

### Q4. 500대 이상으로 확장 가능한가요?
현재 500대는 근사 실시간으로 처리됩니다. KDTree 공간 인덱스 도입 시 O(N²) → O(N log N)으로 개선되어 1,000대 이상도 가능합니다.

### Q5. 예산이 얼마나 필요한가요?
초기 실비행 테스트는 Crazyflie 드론 3~5대(대당 약 50만 원)로 시작 가능합니다. 광주 실증 단계는 정부 R&D 과제(드론 특구, 스마트시티) 연계를 검토 중입니다.

### Q6. 오픈소스인데 기술 유출 우려는?
소프트웨어는 MIT 오픈소스로 공개되어 있지만, 핵심 운용 노하우와 특허 기술은 별도 보호합니다. 오픈소스 전략은 신뢰성 확보와 국제 표준화 참여를 위한 전략적 선택입니다.
